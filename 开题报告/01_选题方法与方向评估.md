# 选题方法与方向评估

> 目标：从“我读了很多 agent memory 论文”收敛到“我能在硕士周期内完成的一个研究问题”。

## 1. 核心判断

你现在缺的不是阅读量，而是**研究范围的收敛**。

一个可开题的硕士题目通常需要同时满足：

1. 有一个真实的失败现象；
2. 有一个可以拆成 2–3 个子问题的核心问题；
3. 有公开数据、可复现基线和可测量指标；
4. 能在 8–12 个月内完成主要实现与实验；
5. 能形成 3 章左右连贯的论文结构；
6. 风险可控，即使主方法效果不理想也能得到有价值的负结果。

## 2. 题目收敛公式

不要从“我要研究 agent memory”开始，而要从下面的公式开始：

> 面向【场景】的【对象】，在【约束】下，解决【问题】，采用【方法】，并用【数据/指标】验证。

示例：

> 面向长期对话智能体的记忆系统，在固定 token / latency 预算下，解决“何时使用摘要、何时回退原始证据”的问题，采用充分性路由与 provenance 回退机制，并在 LoCoMo、LongMemEval 上验证准确率—成本 Pareto。

这个题目包含：

- 场景：长期对话智能体
- 对象：记忆系统
- 约束：固定 token / latency 预算
- 问题：何时使用摘要、何时回退原文
- 方法：充分性路由 + provenance 回退
- 验证：LoCoMo / LongMemEval + Pareto 指标

## 3. 选题四道筛子

### 第一道：失败现象是否明确？

坏题目：

> 提升 agent memory 的效果。

好题目：

> 在固定 token 预算下，结构化记忆在 multi-hop 上更强，但在 single-hop、knowledge update 和 adversarial 查询上经常输给 full-context；系统缺少“何时该回退原文”的机制。

后者有反例、有边界、有可检验假设。

### 第二道：能否拆成 1 个主问题 + 2–3 个子问题？

例如：

- 主问题：预算约束下如何选择记忆访问路径？
- 子问题 1：如何判断摘要或检索证据是否足够？
- 子问题 2：如何在 full-context、RAG、图记忆和原始证据之间路由？
- 子问题 3：如何评价路由带来的准确率、证据保留和成本变化？

如果拆不出来，通常说明题目仍然太宽，或者只是工程 stacks。

### 第三道：数据和基线是否可落地？

至少检查：

- 是否有 1–2 个公开 benchmark？
- 是否有 3–5 个强基线？
- 基线代码或论文设置是否可获得？
- 评测指标是否稳定、可解释？
- 是否能控制 backbone、judge 和 token budget？

### 第四道：是否能在硕士周期完成？

建议按以下时间估算：

- 方法实现：3–4 个月
- 实验与消融：3–4 个月
- 失败重试与补充实验：1–2 个月
- 写作与答辩准备：2–3 个月

如果题目需要：

- 训练大模型；
- 从零搭建多个 memory system；
- 自建大规模多模态数据；
- 同时研究多智能体、权限、安全和多模态；

通常风险偏高。

## 4. 五个候选方向

| 方向 | 核心问题 | 数据/基线基础 | 创新性 | 可行性 | 建议 |
|---|---|---|---|---|---|
| A. 预算约束下的自适应记忆路由与证据回退 | 如何在不同记忆路径之间做成本感知选择？ | LoCoMo、LongMemEval、MemoryAgentBench；TierMem、MRAgent、Evoking、MemGAS | 中高 | 高 | **首选** |
| B. 记忆冲突检测与可追溯更新 | 新信息冲突时如何判断保留、改写、降权或废弃？ | LongMemEval knowledge update、LoCoMo temporal、PersistBench；Mem0、A-Mem、TiMem、VikingMem | 高 | 中高 | **备选** |
| C. 可审计遗忘与记忆治理 | 何时遗忘、如何删除、如何证明没有误删关键证据？ | PersistBench、MEXTRA、MINJA、InjecMEM、eTAMP | 高 | 中 | 适合安全方向 |
| D. 多智能体共享记忆 | 共享粒度、权限、冲突和责任如何设计？ | G-Memory、LTS、MemoryArena | 高 | 低–中 | 不建议首选 |
| E. 多模态/程序性长期记忆 | 视觉、听觉或技能经验如何长期保存与复用？ | M3-Agent、ReasoningBank、ReMe | 高 | 低 | 资源依赖强 |

## 5. 首选方向：预算约束下的自适应记忆路由与证据回退

### 为什么选它

- 它不是“再做一个 memory system”，而是研究一个明确的控制问题：**何时使用哪种记忆**。
- 可直接承接现有工作：TierMem 的 sufficiency router、MRAgent 的 active reconstruction、Evoking 的双过程检索、MemGAS 的多粒度路由。
- 有成熟的公开 benchmark 和较强的直接基线。
- 系统实现可以增量完成，不必从零训练大模型。
- 容易形成“表示—路由—证据回退—评测”的完整论文结构。

### 可能的研究假设

> 在固定 token / latency 预算下，查询级自适应路由能够比固定粒度的 RAG 或单一结构化记忆取得更好的 accuracy–cost Pareto；当高层摘要不足时，provenance-aware 原始证据回退能显著改善 multi-hop、temporal 和 knowledge-update 类问题。

### 主要风险

- 不同论文的 judge、backbone、split 和检索预算不一致；
- router 可能只是在 benchmark 上调参；
- baseline 复现质量决定结论可信度；
- 需要同时报告 accuracy、token、latency 和 storage，否则创新点容易被质疑为“更贵换更高分”。

## 6. 备选方向：记忆冲突检测与可追溯更新

### 适合情况

- 导师偏知识图谱、数据库、可信 AI 或安全；
- 你愿意构造受控的冲突数据；
- 实验室更看重“更新正确性、 provenance、回滚”而不是单一 QA 分数。

### 核心问题

> 当新信息与旧记忆冲突时，系统如何判断哪条记忆应被保留、改写、降权或废弃，并保留可审计证据链？

### 主要风险

- 公开数据对冲突更新的覆盖不足；
- 需要自己构造“旧事实—新事实—干扰事实”测试集；
- 纯规则方案创新性不足，需要引入不确定性、时间有效性或学习型冲突判断。

## 7. 不建议作为首选的方向

- **多智能体共享记忆**：权限、冲突、通信和评测同时展开，硕士周期容易失控。
- **多模态长期记忆**：存储和推理成本高，数据与算力要求高。
- **程序性记忆/技能学习**：需要复杂 agent 环境和长期训练。
- **纯综述型题目**：除非学校明确允许，否则开题通常要求方法或系统贡献。

## 8. 一句话自检

如果你不能用下面五句话写清楚，题目就还需要收敛：

1. 我要解决的现象是什么？
2. 现有方法为什么不够？
3. 我的方法只改变哪一个关键变量？
4. 我用什么数据和基线证明它有效？
5. 如果主实验失败，最可能失败在哪里，备用方案是什么？
