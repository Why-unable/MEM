# 下一步：导师讨论版

> 当前首选方向：方向 B——VikingMem 后续，研究记忆冲突检测、可信更新、provenance 与回滚。
> 本文件目标：把 05 的完整设计压缩成一版可以先和导师讨论的材料，而不是马上写完整开题报告。
> 更新时间：2026-11-27

## 1. 最值得做的下一步

**先做一份 2 页的“导师讨论版研究方案”，而不是直接写 6,000 字开题报告。**

原因：

- 现在最需要确认的是题目边界、导师认可度和资源可行性；
- 如果 2 页方案方向不对，写 6,000 字会浪费大量时间；
- 2 页方案可以快速让导师判断：这个题是否值得做、能不能做、是否需要换方向；
- 导师确认后，再把 2 页方案扩写成学校模板。

## 2. 2 页方案应该包含什么

| 部分 | 内容 | 目标 |
|---|---|---|
| 题目 | 面向知识更新的可追溯事件—实体记忆冲突消解与回滚方法研究 | 让导师一眼知道研究对象和问题 |
| 问题 | 新旧记忆冲突时，如何可信更新、保留证据并回滚？ | 说明不是普通 memory system |
| 与 VikingMem 的关系 | 借鉴 event + entity Memory Base；新增冲突、provenance、版本与回滚 | 说明承接关系，不是复刻 |
| 3 个子问题 | 表示、冲突检测与消解、回滚与评测 | 说明论文可以拆成三章 |
| 技术路线 | event/entity claim → 冲突检测 → 消解动作 → 版本历史 → 检索与审计 | 画成一张简单流程图 |
| 数据与基线 | LongMemEval、LoCoMo、PersistBench；Full-Context、A-Mem、Mem0、MemoryOS/TiMem/TierMem | 证明实验可落地 |
| Pilot | 30–50 个冲突案例 + 一个小型 claim schema 原型 | 证明不是空想 |
| 风险 | VikingMem 不可复现、冲突数据不足、LLM 抽取噪声 | 提前给出降级方案 |
| 需要导师决定的事 | 方向、资源、范围、是否允许构造数据 | 把讨论变成决策 |

## 3. 2–4 周行动清单

### 第 1 周：收窄问题

- [ ] 从 MEM 中选出 15–20 篇直接相关论文：
  - VikingMem、TierMem、TiMem、Mem0、A-Mem、MemoryOS、MAGMA、RecMem、PersistBench、LongMemEval 等。
- [ ] 整理一张“冲突类型—代表论文—现有做法—缺口”表。
- [ ] 明确只研究文本长期对话，不扩展到多模态或多智能体。
- [ ] 写出 3 个候选题目，保留一个首选、两个备选。

### 第 2 周：写 2 页方案

- [ ] 用本文件第 2 节的表格写 2 页初稿。
- [ ] 画出技术路线图：
  ```text
  event extraction
    → entity claim
    → conflict detection
    → resolution
    → version history
    → retrieval / audit / rollback
  ```
- [ ] 明确 3 个研究内容分别对应什么实验。
- [ ] 列出 5 个基线和 6 个指标。

### 第 3 周：做最小 pilot

- [ ] 从 LongMemEval knowledge update 或 LoCoMo temporal 中选 30–50 个样例。
- [ ] 人工标注冲突类型：temporal update、factual contradiction、entity ambiguity、duplicate。
- [ ] 实现一个最小 event + entity claim schema。
- [ ] 保留 source event / raw span，验证 provenance 是否可回溯。
- [ ] 记录 LLM 抽取错误的类型，不要只统计最终准确率。

### 第 4 周：和导师讨论并修订

- [ ] 带着 2 页方案、技术路线图和 3–5 个 pilot 案例找导师。
- [ ] 先问方向是否值得做，再问资源是否足够。
- [ ] 记录导师的反对意见和修改建议。
- [ ] 根据导师意见决定：
  - 继续方向 B；
  - 缩小到只做冲突检测；
  - 或切回方向 A。

## 4. 和导师讨论时必须问的问题

### 方向与价值

1. 这个题目更像是系统论文、数据管理论文，还是 NLP/评测论文？
2. “VikingMem-inspired”是否可以接受，还是必须完整复现？
3. 冲突检测和回滚，哪一部分更适合作为硕士论文的核心贡献？
4. 只做文本长期对话，是否足够？

### 资源与可行性

5. 实验室是否能提供足够的 LLM API 预算做抽取、judge 和多轮实验？
6. 是否允许构造一个小规模冲突测试集？
7. 是否有可用的代码库、向量库或标注人员？
8. 开题前是否要求有初步实验结果？

### 范围与风险

9. 是否需要把安全、隐私或删除机制纳入论文？
10. 如果 VikingMem 无法复现，是否接受 VikingMem-inspired baseline？
11. 如果主方法效果不明显，是否接受“冲突分类 + 评测协议 + 失败分析”的贡献？
12. 论文更希望偏方法创新，还是偏系统实现与评测？

## 6. 讨论后的决策规则

### 继续方向 B 的条件

- 导师认可“冲突检测 + provenance + 回滚”是有价值的问题；
- 可以接受 VikingMem-inspired，而不是完整复现；
- 有基本的 API / 数据 / 时间资源；
- 能构造或找到至少一个小规模冲突测试集。

### 缩小方向 B 的条件

如果资源有限，可以缩成：

> 面向知识更新的 LLM Agent 记忆冲突检测方法研究

先只做冲突检测与分类，不要求完整回滚系统；回滚和审计作为扩展实验。

### 切回方向 A 的条件

- 导师认为冲突数据太难构造；
- 实验室没有足够的 API 预算做多次 LLM 抽取和 judge；
- 现有工作更偏检索/系统优化，而不是数据管理或可信更新；
- 你希望更快复现公开 baseline。
