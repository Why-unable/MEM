# 推荐题目与初步研究设计

> 首选题目：预算约束下长期对话智能体的自适应记忆路由与证据回退方法研究
> 备选题目：面向知识更新的 LLM Agent 记忆冲突检测与可追溯巩固方法研究

## 1. 首选题目

### 题目

**预算约束下长期对话智能体的自适应记忆路由与证据回退方法研究**

### 一句话问题

> 在固定 token、延迟和存储预算下，系统如何判断当前记忆证据是否足够，并在摘要、RAG、图记忆和原始证据之间自适应切换？

### 研究假设

> 查询级充分性判断与 provenance-aware 证据回退，能够在不大幅增加成本的情况下，改善长期对话 agent 在 multi-hop、temporal 和 knowledge-update 任务上的准确率—成本 Pareto。

## 2. 研究问题拆解

### 主问题

预算约束下，长期记忆系统应如何选择记忆访问路径？

### 子问题 1：证据充分性判断

- 当前摘要/检索结果是否足以回答问题？
- 如何识别数字、时间、否定、实体、归因等精确约束缺失？
- 如何用置信度、覆盖率和约束满足度构造路由信号？

### 子问题 2：成本感知记忆路由

- 在 full-context、RAG、摘要记忆、图记忆和原文回退之间如何选择？
- 如何把 token、延迟和存储预算纳入路由决策？
- 规则、分类器、轻量 policy 三种实现方式如何比较？

### 子问题 3：provenance-aware 证据回退

- 高层摘要不足时，如何沿证据链回退到原始 page / turn / event？
- 回退后如何组装最小充分证据？
- 如何评价证据召回、答案正确率和成本？

## 3. 技术路线

```text
对话 / 任务输入
  → 事件、实体、原子事实抽取
  → 三层记忆组织
      1. 摘要层：topic / scene / profile
      2. 证据层：原始 turn / page / event
      3. 关系层：实体、时间、因果或主题图
  → 查询级充分性判断
      - 检索置信度
      - 证据覆盖率
      - 时间 / 数字 / 否定 / 实体约束
  → 路由动作
      - ANSWER：摘要足够
      - RETRIEVE：补充 RAG
      - GRAPH：图关系扩展
      - ESCALATE：回退原始证据
      - FULL-CONTEXT：预算允许时的强基线
  → 最小充分证据组装
  → 生成答案 + 证据链
  → 记录 token / latency / storage
```

## 4. 研究内容

### 研究内容 1：长期记忆的多层表示与证据链

目标：

- 建立摘要层、原始证据层和关系层的统一表示；
- 让每条摘要保留 provenance link；
- 支持按事件、实体和时间回退原始证据。

可复用：

- A-Mem 的原子笔记；
- TierMem 的 summary + raw page；
- VikingMem 的 event + entity；
- TiMem 的时间层次；
- MAGMA 的多关系图。

### 研究内容 2：查询级充分性判断与路由

目标：

- 判断当前 retrieved memory 是否足够；
- 设计 `ANSWER / RETRIEVE / GRAPH / ESCALATE / FULL-CONTEXT` 动作空间；
- 在 token / latency 约束下选择动作。

建议先做：

1. 规则 + 阈值；
2. 轻量分类器；
3. 再比较是否值得使用 LLM policy 或小型 RL。

硕士阶段不建议一开始就上复杂 RL，否则容易把研究变成训练调参。

### 研究内容 3：证据回退与联合评测

目标：

- 回退到原始 turn/page/event；
- 生成最小充分证据集；
- 报告准确率、证据召回、token、延迟和更新正确率。

## 5. 数据集与 benchmark

### 主实验

- **LoCoMo**：single-hop、multi-hop、temporal、open-domain、adversarial。
- **LongMemEval**：information extraction、multi-session reasoning、knowledge update、temporal reasoning、abstention。
- **MemoryAgentBench**：增量多轮交互和多能力评测。

### 扩展实验

- **PersistBench**：记忆不该被使用、跨域泄漏和 sycophancy。
- 自建的 knowledge-update / conflict 子集：旧事实、新事实、干扰事实。

### 数据选择原则

- 先固定 2 个主 benchmark，不要一开始铺开五六个；
- 同一主实验固定 backbone、judge 和 retrieval budget；
- 如果 benchmark 使用 LLM judge，报告 judge 版本和 prompt；
- 记录 adversarial 是否纳入 overall。

## 6. 基线

建议至少保留以下四类：

### 下界 / 上界

- No-Memory
- Full-Context

### 简单检索

- Naive RAG
- Dense Retrieval / BM25

### 结构化记忆

- A-Mem
- Mem0 或 MemoryOS
- MAGMA / MemGAS / MRAgent 中选 1–2 个

### 最近邻强基线

- TierMem
- TiMem
- Evoking / RF-Mem

如果时间有限，基线组合建议为：

```text
Full-Context
+ Naive RAG
+ A-Mem
+ Mem0
+ TierMem
+ 你的方法
```

## 7. 指标

### 效果

- F1
- LLM-Judge accuracy
- knowledge-update accuracy
- evidence recall
- answer coverage

### 成本

- input tokens / query
- total tokens / query
- p50 / p95 latency
- build tokens
- storage size

### 过程与鲁棒性

- escalation rate
- router false-HIT / false-MISS
- evidence provenance accuracy
- adversarial / abstention performance
- judge 方差

## 8. 消融实验

至少包括：

1. 去掉 sufficiency router，固定使用摘要；
2. 去掉 provenance 回退，只使用全局检索；
3. 固定 token budget vs 自适应预算；
4. 规则 router vs 分类器 router vs LLM router；
5. 单层记忆 vs 多层记忆；
6. 是否保留原始证据层。

## 9. 预期贡献

可以写成三条：

1. 提出一种预算感知的多层记忆路由框架，将摘要、图检索和原始证据回退统一到同一决策过程。
2. 设计基于充分性判断和 provenance 的证据回退机制，降低“摘要丢失关键证据”带来的错误。
3. 构建面向长期对话的 accuracy–cost–evidence 联合评测协议，并给出与强基线的系统比较。

注意：不要写成“提出一个全新的记忆系统，全面超过所有方法”。硕士论文更重要的是问题清楚、机制可解释、实验可信。

## 10. 可行性分析

### 技术可行性

- 不需要从头训练大模型；
- 可在现有 memory store / retrieval pipeline 上实现；
- 先做规则 router，再决定是否学习；
- 有公开 benchmark 和强基线。

### 数据可行性

- LoCoMo、LongMemEval、MemoryAgentBench 均可获取；
- 需要额外构造少量冲突/更新测试；
- 可先用现有 evidence 和 baseline 表确定子集。

### 时间可行性

建议 12 个月：

| 阶段 | 时间 | 工作 |
|---|---|---|
| 1 | 第 1–2 月 | 论文精读、协议确定、baseline 复现 |
| 2 | 第 3–4 月 | 多层记忆与 provenance 原型 |
| 3 | 第 5–6 月 | sufficiency router 与路由动作 |
| 4 | 第 7–8 月 | 主实验与消融 |
| 5 | 第 9–10 月 | 补充实验、错误分析、改进 |
| 6 | 第 11–12 月 | 论文写作、预答辩、补充实验 |

## 11. Pilot 实验（开题前最值得做的）

建议在开题前做一个 6–8 周的小实验：

1. 选 LoCoMo + LongMemEval 各一个子集；
2. 复现 Full-Context、Naive RAG、A-Mem、Mem0；
3. 实现一个简单的 summary + raw evidence 两层记忆；
4. 用规则 router 判断是否回退原文；
5. 画出 accuracy vs token / latency 的 Pareto 图。

Pilot 的目标不是证明方法一定赢，而是证明：

- 数据可跑；
- baseline 可复现；
- 存在“摘要不足、需要回退原文”的案例；
- 你的路由假设有初步证据。

## 12. 风险与备用方案

| 风险 | 影响 | 备用方案 |
|---|---|---|
| baseline 复现困难 | 无法公平比较 | 缩小到 3 个强基线，固定同一 backbone 和 judge |
| router 过拟合 benchmark | 结论不可信 | 增加跨 benchmark 测试和规则/学习消融 |
| LLM judge 方差大 | 指标不稳定 | 固定 judge 版本，报告多次运行和人工抽查 |
| 原始证据回退成本高 | Pareto 不占优 | 引入证据缓存、page 级索引和预算上限 |
| 主方法效果不佳 | 论文故事不成立 | 转为“失败分析 + 路由边界 + 评测协议”贡献 |

## 13. 备选题目：记忆冲突检测与可追溯更新

如果导师更偏安全、数据库或知识图谱，可以切换为：

> 面向知识更新的 LLM Agent 记忆冲突检测与可追溯巩固方法研究

核心问题：

> 当新信息与旧记忆冲突时，系统如何判断哪条记忆应被保留、改写、降权或废弃，并保留可审计证据链？

可拆为：

1. 时间有效期与来源可信度表示；
2. 事实冲突、时间冲突和实体冲突检测；
3. 冲突感知的巩固、回滚与 provenance 评价。

数据：

- LongMemEval knowledge update；
- LoCoMo temporal；
- PersistBench；
- 自建“旧事实—新事实—干扰事实”测试集。

风险：

- 需要自己构造冲突数据；
- 纯规则方案创新性不足；
- 需要同时评价 utility、更新正确性和可审计性。

## 14. 与导师讨论时必须确认的问题

1. 这个题目更偏系统、评测还是安全？
2. 实验室是否有可用的 API/GPU 预算？
3. 是否接受构造小规模新数据集？
4. 是否必须使用导师已有项目或代码？
5. 开题时间是否允许先做 6–8 周 pilot？
6. 学校是否要求开题报告中包含初步实验结果？
