# 题目

**面向知识更新的可追溯事件—实体记忆冲突消解与回滚方法研究**

备选题目：

- 基于事件—实体 Memory Base 的 LLM Agent 记忆冲突检测与可信更新研究
- 面向长期对话的可审计记忆冲突消解与版本回滚机制研究

## 二、国内外研究现状

### 2.1 结构化记忆与 Memory Base

> 代表工作：A-Mem、G-Memory、MAGMA、MemGAS、VikingMem、TiMem、TierMem
> 关键判断：event/entity、图、层次和时间结构分别解决了什么？

### 2.2 记忆写入、更新与遗忘

> 代表工作：Mem0、MemoryOS、RecMem、TiMem、TierMem、Nemori、PersistBench
> 关键判断：何时写入、何时巩固、何时回退、何时遗忘？

### 2.3 冲突、可信更新与 provenance

> 代表工作：VikingMem、TierMem、MAGMA、Mem0、PersistBench
> 关键判断：现有工作是否真正区分 temporal update、factual contradiction、entity ambiguity 和 duplicate？

### 2.4 记忆安全与治理

> 代表工作：MEXTRA、MINJA、InjecMEM、eTAMP、PersistBench
> 关键判断：写入权限、provenance、删除、回滚和隐私如何进入系统设计？

### 2.5 研究现状评述

> 提示：总结 3 个缺口，例如：
> 1. event/entity 状态更新缺少显式冲突分类；
> 2. 实体状态缺少版本链和可回滚证据；
> 3. 知识更新正确率、provenance 和回滚能力缺少联合评测。

## 三、研究问题与研究目标

### 3.1 主问题

> 当新事件与已有实体状态发生冲突时，系统如何判断哪条记忆应被保留、改写、降权或废弃，并保留可追溯、可回滚的证据链？

### 3.2 子问题

1. 如何表示带时间有效期、来源、置信度和版本链的 event / entity claim？
2. 如何检测 temporal update、factual contradiction、entity ambiguity 和 duplicate？
3. 如何执行冲突消解、错误更新回滚和 provenance 审计？

### 3.3 研究目标

> 提出一套可追溯的事件—实体记忆冲突消解与回滚框架，并在 LongMemEval、LoCoMo、PersistBench 及自建冲突测试集上验证更新正确性、证据可追溯性和成本。

## 五、研究方法与技术路线

### 5.1 总体技术路线

```text
对话 / 任务输入
  → event extraction
      - 实体、属性、值、时间、来源、证据 span
  → entity claim construction
      - 当前状态 + 时间有效期 + 置信度
  → conflict detection
      - temporal update / contradiction / ambiguity / duplicate
  → conflict resolution
      - keep / merge / supersede / dispute / rollback
  → versioned entity state
      - active claim + history + provenance chain
  → retrieval
      - 按查询时间、实体和任务约束选择当前或历史版本
  → answer + evidence chain
  → audit log / rollback interface
```

### 5.2 关键方法

> 提示：至少写清楚规则/时间约束、语义匹配、LLM 判断三路信号如何组合；为什么第一阶段不直接上复杂 RL。

### 5.3 实现方案

> 提示：说明 memory store、embedding、page/turn 索引、claim table、版本历史和审计日志。

## 六、实验设计

### 6.1 数据集

- LongMemEval：knowledge update、temporal reasoning、abstention
- LoCoMo：temporal、multi-hop、adversarial
- PersistBench：记忆不该被使用、跨域泄漏和 sycophancy
- 自建冲突测试集：旧事实—新事实—干扰事实

### 6.2 基线

- No-Memory
- Full-Context
- A-Mem
- Mem0
- MemoryOS 或 TiMem / TierMem
- VikingMem-inspired event/entity baseline
- 本文方法

> 注意：如果无法复现 VikingMem 原系统，必须写“VikingMem-inspired reimplementation”，不能声称完整复现。

### 6.3 指标

- F1 / LLM-Judge accuracy
- knowledge-update accuracy
- stale-answer rate
- conflict detection precision / recall / F1
- evidence recall / provenance accuracy
- rollback success / post-rollback accuracy
- input tokens / latency / storage

### 6.4 消融

> 写清楚：event-only vs entity-only、无时间有效期、无 provenance、规则 vs LLM vs 混合、无版本历史、无回滚、无 multi-vector rerank。

### 6.5 风险与备选实验

> 写清楚：VikingMem 不可复现怎么办、冲突数据不足怎么办、主方法不占优怎么办。

## 七、预期创新点

1. 提出一种面向知识更新的可追溯事件—实体记忆表示，将实体状态建模为带时间有效期、来源和版本链的 claim set。
2. 设计冲突检测与消解机制，区分时间更新、事实矛盾、实体歧义和重复记忆，并支持争议标记与回滚。
3. 构建面向知识更新、证据可追溯和回滚能力的联合评测协议。

> 提示：创新点控制在 2–3 个，每个都能对应实验。
