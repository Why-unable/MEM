# 国内开题报告写作规范

> 重要前提：国内没有全国统一的硕士开题报告字数和格式，必须以学校/学院模板为准。以下是通用经验值与写作建议。

## 1. 常见篇幅

| 项目 | 常见区间 | 建议默认值 |
|---|---|---|
| 正文 | 3,000–8,000 字 | 6,000–7,000 字 |
| 页数 | 8–15 页 | 10–12 页 |
| 参考文献 | 20–40 篇 | 30–40 篇 |
| 核心研究内容 | 2–4 个 | 3 个 |
| 核心实验 | 3–6 组 | 4–6 组 |
| 技术路线图 | 1 张 | 1 张 |

说明：

- 工程硕士/专业硕士常偏短，约 3,000–5,000 字；
- 学术硕士常偏长，约 5,000–8,000 字；
- 部分学校要求 8,000–10,000 字，也有学校只要求 3,000–5,000 字；
- 如果学校有模板，先满足模板，再谈“写多深”。

## 2. 开题报告是什么，不是什么

### 是什么

- 研究问题的定义书；
- 文献缺口的论证；
- 方法路线的可行性说明；
- 数据、基线、指标和进度的计划；
- 与导师和评委对齐研究范围的契约。

### 不是什么

- 不是论文初稿；
- 不是把所有读过的论文逐篇复述；
- 不是“研究意义”越多越好；
- 不是必须已经有完整实验结果的成果报告；
- 不是为了显得高级而堆砌 RL、多模态、多智能体等关键词。

## 3. 推荐结构

| 部分 | 建议字数 | 核心任务 |
|---|---:|---|
| 1. 研究背景与问题 | 800–1,000 | 说明问题为什么真实、为什么现在值得做 |
| 2. 国内外研究现状 | 1,500–2,000 | 按争议/路线组织，指出缺口 |
| 3. 研究问题与目标 | 500–700 | 1 个主问题 + 2–3 个子问题 |
| 4. 研究内容 | 1,200–1,500 | 每个子问题对应模块、方法和实验 |
| 5. 方法与技术路线 | 1,200–1,500 | 数据流、模块、算法、输入输出、baseline |
| 6. 实验设计与可行性 | 800–1,000 | 数据集、指标、baseline、消融、风险预案 |
| 7. 预期创新点 | 300–500 | 2–3 个，不要写 5 个 |
| 8. 进度安排 | 300–500 | 按月或按季度 |
| 9. 参考文献 | — | 30–40 篇，核心文献 10–15 篇 |

## 4. 各部分要展开到什么程度

### 4.1 研究背景

至少回答：

- 长期记忆为什么是 LLM agent 的关键问题？
- 现有系统在哪些真实任务上失败？
- 失败是“记不住”“找不到”“更新错”还是“成本过高”？
- 为什么这个问题在 2025–2026 年仍然没有解决？

不要只写“大模型很重要、记忆很重要”。

### 4.2 国内外研究现状

不要按论文逐篇罗列。建议按 3–4 条争议组织：

1. **结构记忆 vs 长上下文**：结构一定更好吗？哪些任务上会输？
2. **写入时组织 vs 查询时重构**：记忆应该在什么时候被组织？
3. **固定策略 vs 学习型策略**：规则、RL、元进化各自解决什么？
4. **效果 vs 成本 vs 安全**：准确率之外的 token、延迟、遗忘和注入风险如何评价？

每一节最后都要落到“现有工作的不足”，而不是停在“某某提出了某某方法”。

### 4.3 研究问题

建议写成：

- 1 个主问题；
- 2–3 个子问题；
- 每个子问题对应一个可验证假设；
- 每个假设对应一组实验。

不要写“研究 memory 的表示、更新、检索、安全、多模态和应用”这种没有边界的列表。

### 4.4 研究内容

每项研究内容至少写清楚：

- 输入是什么；
- 输出是什么；
- 方法模块是什么；
- 与哪个 baseline 比；
- 用什么指标判断成功；
- 失败时如何降级。

### 4.5 技术路线

建议画一条明确流水线，例如：

```text
对话/任务输入
  → 事件/实体记忆抽取
  → 摘要层 + 原始证据层 + 图关系层
  → 查询级充分性判断
  → 路由：摘要 / RAG / 图检索 / 原文回退
  → 上下文组装
  → 答案与证据链
```

图上每个模块都应能对应到正文的一段方法和一组实验。

### 4.6 实验设计

至少列出：

- 2–3 个数据集或 benchmark；
- 3–5 个强基线；
- 主指标和辅助指标；
- 消融实验；
- 成本指标；
- 失败案例分析。

### 4.7 创新点

建议 2–3 个，使用可验证的表述：

- “提出……”
- “构建……”
- “设计……”
- “验证……”

慎用“首次”“国际领先”“全面超越”等无法证明的表达。

## 5. 文献综述的写法

推荐结构：

```text
问题定义
  → 三条技术路线
  → 每条路线的代表工作
  → 路线之间的争议
  → 现有评测的不足
  → 本文要解决的具体缺口
```

不要写成：

```text
A 提出了……
B 提出了……
C 提出了……
```

你的 `个人理解/路线分类.md` 和 `vault/40_Maps/Agent Memory 2025+ Baseline Timeline.md` 可以直接用来组织路线和 baseline 演化。开题报告不需要引用全部 52 篇，建议选择 20–30 篇最相关文献，其中 10–15 篇是核心直接对照。

## 6. 开题报告的质量门槛

一个较强的开题报告应该让评委相信：

1. 问题真实存在，不是凭空构造；
2. 现有方法确实没有解决这个问题；
3. 你的方法只改变一个或少数几个关键变量；
4. 数据和 baseline 可获得；
5. 实验能在硕士周期内完成；
6. 即使主方法效果不佳，也能得到可解释的负结果。

## 7. 常见问题

- 题目太大：如“LLM Agent 记忆机制研究”。
- 文献综述太长，研究设计太短。
- 只写“提高效果”，不写 token、延迟和存储成本。
- 只列 baseline 名称，不说明为什么选它们。
- 创新点写了五个，但每个都无法验证。
- 没有失败预案。
- 没有说明数据是否可得、代码是否可复现、算力是否足够。

## 8. 提交前检查清单

- [ ] 题目包含场景、对象、问题和约束
- [ ] 有 1 个主问题 + 2–3 个子问题
- [ ] 每个子问题有对应实验
- [ ] 有公开数据集或可构造数据方案
- [ ] 有 3–5 个强基线
- [ ] 有主指标、成本指标和消融
- [ ] 有技术路线图
- [ ] 有风险与备选方案
- [ ] 参考文献以近五年为主，核心文献足够
- [ ] 长度符合学校模板
